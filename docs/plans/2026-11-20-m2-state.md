# M2: Run State (event log, locks, derived state, `lasagna status`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lasagna can append events to a run's JSONL log under an OS lock, read them back with integrity checks, derive the state of a run and of its child runs by replaying events, and show it with `lasagna status [run] [--json]`.

**Architecture:** Small modules with one job each. `locking` (OS file lock) and `runs` (paths) know nothing about events. `eventlog` is the only code that writes `.lasagna/runs/*.jsonl`, and the only one that reads them. `state` is pure: a list of events in, a `RunState` out. `runtree` adds the I/O around it (child logs, lock probe). `status` renders text and JSON from a `RunTree`; the Typer command in `cli.py` only wires them.

**Tech Stack:** Python 3.11+, stdlib `fcntl`/`msvcrt` for locks, existing `jsonschema` through `schemas.schema_errors("run", ...)`, Typer, pytest, ruff. No new dependency.

**Status:** approved by the user on 2026-11-20 (decisions 1, 2, 3 and 5 as recommended, decision 4 with the exception below).

**Spec:** `harness/PROTOCOL.md` §7 (lock, exit codes), §9 (events and derived states), §11 (`status`), `config/primitives/run.schema.yaml`, `harness/START_PROMPT.md` (M2 scope), `CLAUDE.md`. Fixtures: `tests/fixtures/runs/`.

## Approved decisions

PROTOCOL §9 left these open; the user approved them on 2026-11-20.

1. **Phases that have no event yet.** `status` derives from events only, so a phase that never started does not appear (no `pending` rows). Listing `pending` phases needs the pipeline read from the `definition` commit with `git show`, which is engine work. *Recommendation: events only in M2; `pending` rows arrive in M3.* The `pending` state still exists in the model for the phase between a `start` decision and its `phase_started`.
2. **What `phase_waiting` does to a phase.** `for=trigger` and `for=loop`: the phase is `waiting` and the run is `waiting`. `for=route`: the phase stays `done` (it did complete) and only the run is `waiting`, with the wait listed in `waiting`. A `decision` of the same phase and kind clears the wait. *Recommendation: as written.*
3. **`status` exit code.** 0 whenever the state could be read, whatever the run status (a `failed` run still gives 0, because the command succeeded). 2 for an unknown run id, no `.lasagna/`, outside git, or a corrupt log. *Recommendation: as written.*
4. **Corrupt logs and interrupted writes.** The reader is strict: bad JSON, a blank line, a schema violation, a `seq` that is not exactly 1, 2, 3, ..., a `run` field that differs from the file name, or a first event that is not `run_started` raises `CorruptLogError` naming file and line; no auto-repair. *Exception (user):* a last line **without a trailing newline** is an interrupted write, not corruption. The reader ignores it and returns a warning. The writer, before appending, truncates the file right after the last newline and records the warning (`EventWriter.warnings`; the command that owns the writer prints them to stderr). Every event is written with a single append followed by flush and `fsync`. This is recorded in PROTOCOL §9 (local, in Italian).
5. **Interrupted detection.** Per §9: if no process holds the run's lock, a `running` phase whose mode is not `manual` is reported as `interrupted` (flag in JSON, suffix in text) with the hint `run lasagna resume <root run>`. `resume` itself arrives in M5, the hint is printed anyway because §9 requires it. *Recommendation: as written.*

## Global Constraints

- Everything committed is in English. Never `git add harness/`.
- Only Lasagna writes `.lasagna/runs/*.jsonl`: append-only, `seq` increasing by 1, one OS lock per run (`fcntl` on macOS/Linux, `msvcrt` on Windows) on `runs/<run-id>.lock`, released by the OS if the process dies.
- Current state is always derived by replaying events; nothing is stored besides the log.
- No background processes. No new runtime dependency. `pathlib` everywhere, LF line endings, UTF-8, POSIX paths in anything printed.
- Events are validated with the `run` schema before being written, and each one is written with one append, flush and `fsync`. A last line without a trailing newline is an interrupted write (decision 4). Timestamps are UTC, `YYYY-MM-DDTHH:MM:SSZ`.
- Exit codes (PROTOCOL §7): 0 ok, 2 usage or validation error. Every command has a one-line docstring and every option and argument a `help` text.
- Tests never call Claude, OpenCode or the network. Tests must pass on Windows, Linux and macOS, so lock tests use real OS locks, not mocks.
- A task is done only when `uv run pytest` is green and `uv run ruff check . && uv run ruff format --check .` is clean. Check the exit code of the test run, not just its last lines.
- Branch `m2-state`, created from `m1-validation` while PR #2 was still open (it holds the same M1 code, so it merges cleanly after PR #2 is merged into `develop`). Commit messages: imperative English, ending with the `Co-Authored-By` line from the session. Stop after Task 19 for review. Never pipe test or lint commands (for example into `tail`): check their exit code directly.

### Task 17: State derivation (pure)

**Files:**
- Create: `src/lasagna_cli/state.py`, `tests/test_state.py`

**Interfaces:**
- Consumes: the event dicts from `read_events`.
- Produces (all `@dataclass(frozen=True)`):
  - `Waiting(phase: str, for_: Literal["trigger", "route", "loop"], by: str)`
  - `DecisionRecord(kind: str, by: str, value: str)`
  - `PhaseState(phase: str, state: Literal["pending", "waiting", "running", "done", "skipped", "pruned", "failed"], iteration: int | None, actor: str | None, pipeline: str | None, child_run: str | None, mode: str | None, inputs: dict[str, str], outputs: dict[str, str], commit: str | None, exit_code: int | None, duration_ms: int | None, reason: str | None, detail: str | None, decisions: tuple[DecisionRecord, ...])`
  - `RunState(run_id, pipeline, status: Literal["running", "waiting", "done", "failed", "cancelled"], by, parent: tuple[str, str] | None, worktree, branch, base_commit, definition, inputs: dict[str, str], bind: dict[str, str], started_at: str, completed_at: str | None, outputs: dict[str, str], phases: tuple[PhaseState, ...] (order of first appearance), waiting: tuple[Waiting, ...], last_seq: int)`
  - `derive_state(events: list[dict]) -> RunState`.

Rules (decisions 1 and 2 above):

| Event | Effect |
|---|---|
| `run_started` | Sets the run fields; status `running`. |
| `phase_waiting` | Adds `Waiting`; phase `waiting` for `trigger` and `loop`, unchanged for `route`. |
| `decision` | Removes the matching `Waiting`; appends a `DecisionRecord`; phase `waiting` becomes `pending` after a trigger decision and `running` after a loop decision. |
| `phase_started` | Phase `running`; takes `iteration`, `actor` or `pipeline` and `child_run`, `mode`, `inputs`; clears `reason`, `detail`, `exit_code`, `commit` of the previous attempt. |
| `phase_completed` | `done`; takes `outputs`, `commit`, `duration_ms`, `exit_code` if present. |
| `phase_failed` | `failed`; takes `reason`, `detail`, `exit_code`. |
| `phase_skipped` | `skipped` if `reason` is `trigger`, `pruned` if `pruned`. |
| `run_resumed` | `completed_at` cleared; status recomputed. |
| `run_completed` | Status `done`, `failed` or `cancelled`; `completed_at`; `outputs`; `waiting` cleared. |

Status without a `run_completed`: `waiting` if `waiting` is not empty or some phase is `running` with mode `manual`, otherwise `running`. After `run_completed` `failed` followed by `run_resumed` the status is computed again, so it returns to `running`.
