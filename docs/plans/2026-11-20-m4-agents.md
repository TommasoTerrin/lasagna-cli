# M4: Agents (cycle, params, bind, timeout, loop, interactive, agent decisions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pipeline whose phases are run by agents (any program launched from the command line) runs end to end: the `check` / `inject` / `run` / `cleanup` cycle, params and model aliases, harness variables, `--bind`, `timeout`, `loop`, interactive phases that take over the terminal, and decisions taken by agents. The `spec-to-code` example runs from `start` to `done` with fake agents.

**Architecture:** The engine of M3 stays the loop "derive state, ask `flow`, run the step, append events". New behaviour lives in small modules the engine calls: `params` (what an agent receives), `harness` (skill and MCP variables), `bind` (actor replacement), `agentcycle` (the four commands in order), `decisions` (agent decisions and the worktree snapshot around them). `runner` gains a timeout and a foreground mode. A loop is replayed from events (iteration number and `loop` decisions), so a wait for a human inside a loop needs no new event.

**Tech Stack:** Python 3.11+, git CLI through `subprocess`, existing `FileLock`, `EventWriter`, `derive_state`, `Engine`, `run_shell`. No new runtime dependency.

**Spec:** `harness/PROTOCOL.md` §3 (attori, `--bind`), §5 (fasi, `loop`, `timeout`), §6 (decisioni, espressioni, variabili d'ambiente), §7 (processi, interruzioni, timeout, ciclo di vita), §8 (commit), §9 (eventi), §10 (regole di avvio), §11; `harness/START_PROMPT.md` (M4); `config/primitives/agent.schema.yaml` and `phase.schema.yaml`; `CLAUDE.md`; the M3 plan for the modules it built.

**Status:** APPROVED by the user on 2026-11-20: all 12 proposals, with three clarifications (proposal 7: the file name uses the dashed phase name; proposal 10: an M5 test; proposal 11: a note for the M6 checklist), the split into M4a and M4b, the engine split as Task 34 (pure refactoring) and the interactive mode for `lasagna phase run`. The rules are recorded in the local `harness/PROTOCOL.md` (§3, §6, §7, §9). Not started: Task 34 begins on the user's go. Branches `m4a-agents` (Tasks 34-40) and `m4b-interactive` (Tasks 41-43).

## Approved proposals

All approved, with the clarifications marked below.

1. **Split M4 in two**, like M3. M4a (Tasks 34-40): the agent cycle in headless mode, params, harness variables, `--bind`, `timeout`, and `loop` with machine or human `until`. M4b (Tasks 41-43): interactive phases, agent decisions, and the `spec-to-code` run with fakes. Two branches (`m4a-agents`, `m4b-interactive`), two PRs, a stop for review after each. *Recommended: the two halves share no code except `agentcycle`, and M4b touches the terminal and `git reset --hard`, the riskiest parts.*
2. **`phase_started.params` holds the values the agent receives**: expressions resolved, defaults filled, the `model` alias already replaced by the real id. *Recommended: it is what telemetry needs to reproduce the call.*
3. **`LASAGNA_SKILLS` lists skill folders** (`.lasagna/pipelines/<p>/harness/skills/<name>`), `LASAGNA_MCP` lists the MCP files (`.../harness/mcp/<name>.json`), one per line, relative to the worktree, pipeline-level entries first, then the phase's, without duplicates. `LASAGNA_MAIN_SKILL_DIR`, `LASAGNA_MAIN_SKILL_NAME`, `LASAGNA_SKILLS` and `LASAGNA_MCP` are **unset** when empty, so `[ -z "$LASAGNA_MAIN_SKILL_DIR" ]` works. *Recommended.*
4. **`LASAGNA_MAIN_SKILL_NAME` is the full phase name with `/` replaced by `-`** (`bug-fix/tdd/red` gives `bug-fix-tdd-red`, as in §6). `LASAGNA_MAIN_SKILL_DIR` is `.lasagna/pipelines/<pipeline>/harness/phases/<phase-id>` (relative, forward slashes). *Recommended.*
5. **Failures of the agent cycle** (§7): a `check` exiting non-zero gives `check_failed` with `detail` `check <n> (<command>) exited <code>`; `inject`, `run` or `cleanup` exiting non-zero gives `exit_code` with `detail` `inject`, `run` or `cleanup`. `cleanup` always runs. If `run` failed, its failure is the one reported even if `cleanup` fails too. If `run` succeeded and `cleanup` fails, the phase fails with `exit_code` / `cleanup`. *Recommended: §7 fixes the first two rules, the last two fill a gap.*
6. **`timeout` applies to the main command of a phase, per iteration**: `with.command` of machine phases and `run` of agents. On expiry the process tree is killed and the phase fails with `timeout`, `detail` `exceeded <value>`. `check`, `inject`, `cleanup`, decisions and the command of `lasagna phase run` have no timeout (the user decided that a command launched by a human is attended, see proposal 11). *Recommended.*
7. **Loop replay.** The iteration's `$LASAGNA_OUTPUT` has a fixed name, `<worktree>/.lasagna/runs/<run-id>.<phase>.<iteration>.out`, where `<phase>` is the **full phase name with `/` replaced by `-`** (the same form as `LASAGNA_MAIN_SKILL_NAME`, so no subfolders are created; approved clarification). After a human `decide stop` the engine verifies and commits the phase from the file of the last iteration without re-running anything. Decisions of any kind keep using fresh numbered files. A pending loop decision for iteration *n* is the case "`n - 1` loop decisions recorded"; a decided one is "`n` recorded". *Recommended: no new event and no change to `derive_state`.*
8. **Loop at the limit.** After iteration `max_iterations` the `until` decision is still taken: `stop` completes the phase, `continue` fails it with `max_iterations`. A machine `until` check follows the usual rules (`decision=` written wins over the exit code). *Recommended.*
9. **Agent decisions** (M4b): the `prompt` is resolved, then the fixed instruction is appended, then the agent runs headless with `LASAGNA_PARAM_PROMPT` set to that text and every other param at its definition default (the `model` default goes through the alias). The fixed instruction texts are in Task 42 and are English, since they are code. A `check` of the agent failing gives `check_failed`; a missing or invalid value gives `invalid_decision`. *Recommended.*
10. **Worktree around an agent decision** (§6): for `trigger` and `route` the worktree is reset to its last commit afterwards (`git reset --hard`, `git clean -fd`, no `-x`). For `loop.until` a temporary snapshot commit is taken first, restored after the decision, then removed with `git reset --mixed` so the iteration's work stays and the phase still has one commit. *Recommended, as §6 states.*
11. **Interactive mode** (interactive agent phases **and** the command of `lasagna phase run`, as decided by the user): the command runs in the terminal's own process group with stdin, stdout and stderr inherited and no timeout; Lasagna ignores SIGINT while it runs and restores the previous handler afterwards (so the Ctrl+C handling of M3 Task 32a is unchanged outside the command). Windows uses the same `signal.SIG_IGN` approach. A Ctrl+C then reaches only the command; if it dies, its exit code decides the phase. A real terminal cannot be tested in CI: the tests check the handler and the process-group options, and the acceptance checklist covers the rest by hand. Recorded in PROTOCOL §7. *Recommended.*
12. **`--bind` rules**: `phase=actor`, repeatable; the phase id must belong to the started pipeline; the new actor must exist and have the same type as the original; it must accept every key the phase passes in `with`, and every required param of the new actor must be provided by the phase or have a default; the result goes into `run_started.bind` only when `--bind` is used. The engine uses the bound actor everywhere (`phase_started.actor`, params, cycle). `resume` (M5) reads `bind` back. `--as` is already done in M3. *Recommended.*

## Decisions of 2026-11-24 (before M4b)

Taken by the user after merging M4a (PR #6), recorded in `harness/PROTOCOL.md` (§3, §6, §7, §10). Tasks 40b and 40c implement them before Task 41.

1. **A `loop` on a phase run by a human is a validation error** (§10), a final rule and no longer "not supported yet": the person does not close the phase until they are done, so a loop adds nothing. It moves from `support.unsupported_features` to `lasagna validate`.
2. **A failed `check` of an agent** records `reason: check_failed` **and** `exit_code` in `phase_failed` (§7), for phases and for agent decisions alike.
3. **Workflow**: the local pre-commit hook runs ruff with `--no-cache`; every test on the output of the CLI goes through one helper that strips ANSI codes (`tests/conftest.py`: `plain(text)`).
4. **Agent permissions.** On the user's Windows PC the bypass mode of Claude Code is disabled by policy; with `acceptEdits` Claude writes files in the worktree but cannot use Bash, so it cannot read `$LASAGNA_OUTPUT`.
   a) New expression **`${{ lasagna.output }}`**: the path, relative to the worktree and with forward slashes, of the same file named by `$LASAGNA_OUTPUT` in the current execution (the phase iteration or the decision). Lasagna creates the file empty before launching the command; `$LASAGNA_OUTPUT` stays. Allowed only in texts read by whoever writes that file (user's choice): `with` values (not `command`) of phases run by an agent and `prompt` of agent decisions; a validation error anywhere else (phase `inputs`, output `path`s, human `instructions`, pipeline `outputs`).
   b) The fixed instruction appended to agent decision prompts names the file by its explicit path (relative to the worktree, the value of `${{ lasagna.output }}` for that decision), not the environment variable. Texts in Task 42.
   c) The `claude` and `opencode` actor templates declare a `permission-mode` param, default `acceptEdits`. `claude`: `run` and `run_interactive` pass `--permission-mode "$LASAGNA_PARAM_PERMISSION_MODE"`. `opencode` (v2.3.0, tested for real on 2026-11-24: with no config `opencode run` edits files and runs commands; a permission set to `ask` is auto-rejected in a headless run, which still exits 0; `--auto` approves `ask` but not `deny`; `OPENCODE_CONFIG_CONTENT` is honoured only with `--standalone`, since the client otherwise talks to the background service). Same values as claude (user's choice): `acceptEdits` → `--standalone` with `OPENCODE_CONFIG_CONTENT={"permission":{"edit":"allow","bash":"ask"}}`; `bypassPermissions` → `--auto`; `default` → no flag; any other value fails the actor's `check`.
   d) The prompts and skills of `examples/pipelines/spec-to-code` and of the fixtures use `${{ lasagna.output }}` instead of asking the agent to read the environment variable. M6 note: the README explains permissions (phases that must run commands need broader permissions, configured in the actor file).

## Global Constraints

Copied from the M3 plan and still in force.

- Everything committed is in English. Never `git add harness/`.
- User commands (`with.command`, `check`, agent commands) run with `bash -c` on every OS through `shell.host_bash()`; `shell_env(sys.platform)` is added to every command environment. Values reach commands only as environment variables; `${{ }}` is never interpolated into a shell string, and is not allowed in any field executed as a command.
- Lasagna's git calls and every phase command run without the local git variables (`gitops.git_env()`, `runner.build_env(..., drop=local_git_env_vars())`).
- Before setting its own variables Lasagna removes every inherited `LASAGNA_*` variable. `LASAGNA_WORKTREE`, `LASAGNA_OUTPUT`, `LASAGNA_STATE` are absolute; all paths use forward slashes; `LASAGNA_MAIN_SKILL_DIR`, `LASAGNA_SKILLS`, `LASAGNA_MCP` are relative to the worktree.
- Only Lasagna writes `.lasagna/runs/*.jsonl`, through `EventWriter`, while holding the run lock. No background process.
- During a run, actors, pipelines and config are read from the `definition` commit. A phase ends with `git add -A` and `git commit --no-verify`, or no commit and `commit: null`; one commit per phase, whatever the iterations.
- Exit codes (§7): 0 done, 1 failed, 2 usage or validation error, 3 waiting for a human, 130 Ctrl+C.
- Every command has a one-line docstring and every option and argument a `help` text.
- Tests never call Claude, OpenCode or the network. Agents in tests are fake agents: actor files whose commands run a Python script from `tests/fakes/` through `sys.executable` (path passed with `to_bash_path`, double-quoted, since it may contain spaces). Git tests use real repositories in `tmp_path`. Tests pass on Windows, Linux and macOS; a test that needs a real terminal or signal is replaced by one that checks the observable state (handler, flags).
- Workflow: the local pre-commit hook runs the full suite and both ruff checks (ruff with `--no-cache`), never bypass it. Tests on CLI output compare text through the single ANSI-stripping helper `plain()` of `tests/conftest.py`. Never pipe test or lint commands. Commit messages are imperative English ending with the `Co-Authored-By` line. Stop after Task 40 and after Task 43 for review.
